## FINAL ROLE FLOW

### Employee

`Shop Home → Daily Calling / Start Order → Logout`

### Manager

`Shop Home → Employee work + Manager Dashboard → Logout`

### Admin

`Shop Home → Employee work + Manager work + Admin Dashboard → Logout`

### Super Admin

`Super Admin Login → Super Admin Dashboard`

Super Admin is outside the shop-user flow.

## FINAL ORDER FLOW

Exactly the same for Admin, Manager and Employee:

`Home → Medical List → Select Medical → Product List → Select Products → Final Order → Submit Order`

Do not jump directly from Home to Final Order. Browser Back should return through the normal sequence.

## FINAL DAILY CALLING FLOW

`Home → Daily Calling → Today's Medicals → Medical Name + Mobile → Tap Mobile → 📞 Call → isCall automatically recorded → Picked / Not Picked`

`isCall` is generated by the system. Employee cannot manually select it. A 10-second minimum interval prevents rapid repeated call events. Suspicious/poor calling activity is an Admin-side concern and is not shown to employees.

After a call, there is **no Create Order button** in the calling flow. If the user wants to order, they return to Home and use the normal Order flow.

## MULTI-TENANT RULE

The shop URL is the tenant identity:

- `/shop/hind-pharma`
- `/shop/india-medical-agency`

The same Home UI is reused; separate HTML files are not created per shop. Tenant name, logo, users, medicals, products, orders and calling data must remain isolated by tenant/admin ID.

## SUPER ADMIN SHOP CREATION

Super Admin can create a new shop application with:

- Shop name
- Subtitle
- Address
- Phone/email
- DL 20B / DL 21B if available
- FSSAI if available
- GSTIN if applicable
- Shop logo
- Barcode if applicable
- UPI
- Admin name
- Admin username

The application starts as `pending_payment`. **Admin generation happens only after payment confirmation.**

## DATABASE

SQLite is the final persistent database.

Super Admin tables use the `superAdmin` prefix:

- `superAdminTenants`
- `superAdminApplications`
- `superAdminPayments`
- `superAdminActivityLogs`

Operational tenant tables include `admins`, `users`, `medicals`, `products`, `orders`, `order_items`, `calling_logs` and `audit_logs`.

## GITHUB PAGES TESTING NOTE

The current website is hosted on GitHub Pages, so the browser demo uses the tenant registry for static-page testing. The real persistent multi-tenant source of truth is the SQLite/FastAPI backend.
